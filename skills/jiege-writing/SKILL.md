# 杰哥写作

面向中文学术写作：从作业要求到可提交的 Word 成稿，一次走完。三条底线是**格式零瑕疵、文献可核验、行文不像机器写的**。

## 适用范围

**适合**：课程论文、读书报告、文献综述、方法学评述、研究方案初稿。篇幅 3000–8000 字，一二级标题结构，10–30 条参考文献。

**不适合**：学位论文。三级标题（`2.1.1`）会直接抛异常，图表题注与目录页码也没有实现。要写毕业论文，先把末尾「已知限制」那几条补齐。

**参考文献必须人工复核**。脚本给的是通行默认值，学校的模板常在这几处不同：GB/T 7714 用 2015 版还是 2025 版、中文条目全角还是半角标点、列不列 DOI。交稿前逐条对一遍学校给的示例。

## 快速开始

```bash
pip install python-docx lxml
python scripts/build_docx.py assets/example_spec.json -o 试排.docx
python scripts/check_docx.py 试排.docx --strict
```

看完 `assets/example_spec.json` 就知道 spec 长什么样，改内容即可开工。

## 六步工作法

### 第一步：读要求，先确认再动笔

1. **先看版式，再提文字**。要求可能是 PDF、Word、手机截图、聊天记录里的照片，处理方式见 `references/input-formats.md`。字号、行距、加粗这些信息只存在于版式里，纯文本提取会全部丢失，所以要先渲染成图看一遍，再用文本抠细节。扫描版 PDF 与图片不要走 OCR，直接看图。
2. 逐条拆成**可核对的清单**：主题范围、必备组成部分、关键词个数、外文文献下限、总文献下限、正文字数下限、字体字号、行距、参考文献字号。
3. **选题不明确就先问**，别猜。用户说「你看着来」时，按用户的研究方向选最贴合的，并在交付时说明选择理由。
4. **把口头约束也问清**，这些往往不在作业文件里：篇幅区间（作业只给下限时，问一句上限）、要不要图表、有没有忌讳的表述、署名与学号是否要写。
5. 把清单写成表格，交付时逐项打勾。用户最容易在「字数」「文献数量」「字体」三项上被扣分。

配套清单见 `references/checklist.md`，可直接拿去逐项核对。

### 第二步：核验文献，再写正文

顺序不能反：先有可核验的文献，正文才有出处可引。

1. 定选题后先列候选文献（方法学原始文献 + 近五年综述 + 中文权威期刊），逐条查 DOI 与卷期页。
2. 核验渠道优先级：Crossref `api.crossref.org/works/{DOI}` ＞ 期刊官网文章页 ＞ 搜索引擎快照。**按题名检索会错配**，必须用 DOI 复核。
3. 中文文献查期刊官网（如 `bulletin.cas.cn`、`pedologica.issas.ac.cn`、`ecologica.cn`、`tcsae.org`）；知网检索页是 JS 渲染，抓不到条目。
4. Crossref 连续请求会 429，间隔 1.5–2 秒并退避重试；中文期刊在 Crossref 覆盖有限，`filter=prefix:` 多半返回空，走官网更稳。
5. 著录格式、作者人数规则、常见错误见 `references/gbt7714.md`。

### 第三步：先定字数，再搭结构

1. **总字数从输入来，不用默认值**。作业文件写明了照文件；只给下限（「不少于 3000 字」）就问一句上限；文件没写也没提，就问用户要多少，给 3000 / 5000 / 8000 三档让他选。不要替用户假定一个数字，写长了嫌注水、写短了不够分，返工的都是你。
2. **同时确认统计口径**。纯正文、Word 字数统计（含表格）、页数，三者能差三四百字。学校多按 Word 统计查，而脚本算的是纯正文，交付时两个数都要报。
3. **按占比分到节，写进 spec 的旁注**。`某节字数 = 目标字数 × 占比`，算完记下来，写完逐节核对。配比表与三档示例见 `references/writing-guide.md`。
4. 一级章节控制在 5–7 个；二级小节只在内容确实长（>800 字）的地方设，避免「一节能塞三四百字就不该单独成节」。
5. 每个二级小节 200–500 字为宜，低于 150 字就是偏薄，要么并节，要么补内容。
6. **默认两级标题，三级要用户明确要求**。一般课程论文两级就够，多一层会把结构切碎、编号拉长。脚本虽然已支持 `2.1.1`，但不要自作主张加上去；只有使用者点名要三级，或单个二级小节确已超过 800 字且内部有两个以上并列子主题时，才设这一级，设了就要按分点写足，不能只剩一个空壳小节。
7. 写作时同步跑去 AI 味规则（`lieflat-less-ai-tone` 技能），重点是：不写「不是…而是…」，不堆三个以上顿号并列，不连续同构句，段首不用「然而/此外/因此」，不用破折号制造揭晓。

### 第四步：生成 docx

**正文与排版分开放**。把稿件写成一份独立的数据文件（`spec.json`），排版由脚本消费。这样改文字不动格式、调格式不动文字；一篇稿子往往要改七八轮，混在一起迟早出事。

```bash
python scripts/build_docx.py spec.json -o 论文.docx
python scripts/build_docx.py spec.json --check     # 只校验引用关系
```

spec 结构见 `assets/example_spec.json`，完整案例见 `references/case-study.md`。要点：

- `blocks` 是 `[["h1","1 引言"],["p","正文…"],…]`。标题必须写成「编号 + 半角空格 + 标题文字」，且编号最多两级（`1` 或 `2.1`）；写成 `1.引言` 或 `2.1.1 x` 会让脚本抛 `AttributeError`。
- 正文用 `{{文献键}}` 标引用，脚本按**首次出现顺序**自动编号，无需手工排号。
- 多条文献合并引用写 `{{a|b|c}}`，脚本按首次引用顺序编号后自动压成 `[1-3]`：连续 3 条以上用短横线，2 条仍用逗号，不连续写成 `[1,3-5]`，乱序输入先排序。多引用是纯文本，不能 Ctrl+单击跳转；单条引用仍是可跳转的域。
- `refs` 支持两种写法：8 元组 `[作者, 题名, 刊名, 年, 卷, 期, 页码, DOI]`，或字典（非期刊类型必需，可指定 `type` 为 M/D/C/R）。
- 章节互引写 `{{@2.3}}`，脚本插入标题编号域。
- `word_target` 可选，写成 `[4500, 5000]` 或 `3000`。构建与自检都会拿正文汉字数对照它，越界时打印提示但不中断；字数口径见 `references/writing-guide.md`。

脚本已处理下列易错项，**不要重复实现**：中文宋体 + 西文 Times New Roman 的四字体位、中文标点的 `hint="eastAsia"`、希腊字母单独成 run、参考文献 `[1]` 自动编号配 21 pt 制表位、`REF … \n \h` 交叉引用、上标统一小四、逐段关闭孤行控制、兼容模式提到 15。

**表格需要自行补**。`build_docx.py` 没有 table 类型的 block。做法是在正文里放占位段 `__TABLE_1__`，构建后用 `python-docx` 定位替换为三线表；实现要点见 `references/case-study.md`。

### 第五步：交付前自检

先跑脚本，再人工看。

```bash
python scripts/check_docx.py 论文.docx --strict
```

脚本读回 docx，打印字体组合、字号分布、上标数量与字号、行距、孤行控制、域与书签数、文献条数与引用覆盖、字数、标题清单，异常项打叉并以退出码 1 结束。

| 检查项 | 脚本判定 |
|---|---|
| 字体 | `ascii/hAnsi/cs` 是否全为 Times New Roman，`eastAsia` 是否全为宋体，有无 `asciiTheme` 残留 |
| 中文 run | 含汉字或中文标点的 run 是否都带 `w:hint="eastAsia"` |
| 希腊字母 | α、β 所在 run 的 `eastAsia` 是否为 Times New Roman |
| 上标 | `sz` 是否全部一致 |
| 行距 | 是否全篇统一 |
| 孤行控制 | 是否每段 `w:widowControl w:val="0"` |
| 交叉引用 | 域是否都指向存在的书签、是否都带 `\h` |
| 文献覆盖 | 正文引用条数与文末条目数是否相等 |
| 字数 | 汉字数、英文词数、Word 近似字数 |

脚本查不出来的，必须人工过一遍：

- 分页效果（哪一页断开难看、标题是否落在页底）
- 中英文混排的空格、括号半全角是否统一
- 是否有「由 Python 生成」「本表由程序绘制」之类制作过程信息（docx 的 `docProps/core.xml` 里还有 `creator=python-docx`，对外发布前清掉）
- 正文有没有残留的 `{{}}` 标记
- **表格与图**：`check_docx.py` 的段落遍历只取 `body` 直接子级，表格内段落的行距、缩进、字号异常一律查不出来，必须目视

### 第六步：交付说明

回复里给三样东西：改了哪里、还剩什么要人工确认、文件在哪。**不要只给一句「已完成」。**

文件放到用户平时找得到的位置（桌面或指定目录），命名带姓名，不要用「终稿」「最终」这类后缀——真到了要区分版本时，靠时间戳而不靠名字。

## 格式硬指标

默认按下面这套走；学校另有规定时以用户提供的文件为准，逐条对照覆盖。

| 元素 | 字体 | 字号 | 其他 |
|---|---|---|---|
| 中文题目 | 宋体 | 小二（18 pt） | 加粗、居中 |
| 作者 | 宋体 | 四号（14 pt） | 加粗、居中；不署名时留空，脚本会多出一个空段落，需手工删 |
| 「摘要：」「关键词：」标签 | 宋体 | 小四（12 pt） | 加粗 |
| 摘要、关键词正文 | 宋体 | 小四 | — |
| 各级标题 | 宋体 | 小四 | 加粗、左对齐；段前/段后：一级 18/6、二级 12/4、三级 6/3 pt |
| 正文 | 宋体 | 小四 | 首行缩进 2 字符、1.5 倍行距、两端对齐 |
| 参考文献标题 | 宋体 | 小四 | 加粗 |
| 参考文献条目 | 宋体 | 五号（10.5 pt） | 悬挂缩进 21 pt，编号 `[1]` |

西文与数字一律 Times New Roman；全文不得混入其他拉丁字体。完整 OOXML 键值见 `references/format-spec.md`。

## 图表规范

### 文字字体

图和表里的文字，不分位置，统一两条：英文与数字用 **Times New Roman**，中文用 **宋体**。

范围包括图题、表题、图内文字（轴标签、刻度标签、图例、数据标注）、表内文字、表注。图和表的题注本身是正文段落，五号加粗居中；图内文字按图宽 8–9 cm 取 9 pt（约小五），不要出了大图再缩——缩了字号就不受控。

表格的做法见 `references/case-study.md` 第 4 节：每个单元格的 run 都要设 `w:rFonts`，含中文的还要带 `w:hint="eastAsia"`，否则 Word 会拿西文字体去排中文。`check_docx.py` 对表格内段落是盲区，这部分只能靠脚本设置正确 + 目视复核。

插图用 `scripts/plot_style.py`，字体、线宽、刻度方向都定死了：

```python
from plot_style import apply_style, new_axes, save, audit

apply_style()
fig, ax = new_axes()                       # 8.5 × 6.0 cm
ax.plot(x, y, lw=1.2, color="#333333")
ax.set_xlabel("灌溉定额 / (mm)")
ax.set_ylabel("土壤含盐量 / (g·kg⁻¹)")
save(fig, "fig1.png")                      # 600 dpi 白底
print(audit(ax))                           # 空列表才算过
```

它靠 matplotlib 的 font fallback 逐字符换字体：`font.family = ["Times New Roman", "SimSun"]`，英文数字命中前一个，中文落到后一个。前提是系统里有 SimSun（Windows 自带）。

### 坐标轴对齐

轴线与刻度线错位，几乎只有一个原因：**移动了 spine 却没有同步移动刻度**。

`new_axes()` 把 spine 固定成 `('axes', 0)`，即轴范围起点，不做 outward 外扩。下面三种写法会破坏对齐，不要用：

- `ax.spines['left'].set_position(('outward', 10))` —— 轴外移，刻度留在原位
- `ax.spines['bottom'].set_position('zero')` —— 轴穿到 y=0 处，刻度仍在底部
- 手动 `set_xticks` 之后又改 `spines` 位置

出图前跑 `audit(ax)`，它查五件事：spine 位置是否被移过、刻度是否在左和下、刻度线长度是否为 0、轴是否含原点、图内有没有多余的标题。

### 轴范围

**坐标轴默认包含原点。** `new_axes()` 记下 `include_zero=True`，`save()` 与 `audit()` 出图前都会把轴拉到 0，不看数据是否贴着零点。

柱状图必须从 0 起，否则柱长的比例直接失真。折线图同样建议从 0 起——从 1 起会让人误以为数据离开零点很远，客观上放大了趋势。

只有数据整体远离 0（pH 6–8、地温 15–25 ℃、水深 3–5 m）才用 `new_axes(include_zero=False)`，且图注里必须写明「x 轴已截断」。对数轴不受此限。

图内不放标题。标题写进图题（「图 1  盐分随灌溉定额的变化」），图本身留空。

## 参考文献要点

- 2015 版与 2025 版并存，按学校文件走，不要自作主张。默认输出两版通用格式，**不列 DOI**。
- 责任者超过 3 人，取前 3 位后加「等」（中文）或「et al」（西文）；3 人以内全列。
- **标点按语种切换**，这是最常被挑的一处。中文条目全角，西文条目半角：

  `朱永官，沈仁芳，贺纪正，等．中国土壤微生物组：进展与展望[J]．中国科学院院刊，2017，32（6）：554-565+542．`

  `Louca S, Polz M F, Mazel F, et al. Function and functional redundancy in microbial systems[J]. Nature Ecology & Evolution, 2018, 2(6): 936-943.`

- 文献必须是真文献。宁可少一条，不可编一条。核验不过的条目直接删掉。
- 详细规则、六类文献格式、常见错误见 `references/gbt7714.md`。

## 已知限制

这些是当前版本的硬边界，遇到时先告诉用户，不要硬扛。

| 限制 | 现象 | 绕法 |
|---|---|---|
| 表格 | spec 无 table block；check 对表格盲区 | 占位段 + 后处理，见 case-study |
| 图与表题注 | 无题注机制，无交叉引用 | 在 Word 里手工「插入题注 + 交叉引用」 |
| 页码与目录 | 完全未实现 | Word 里手工加页脚 PAGE 域 |
| 页边距 | 写死上下 2.54、左右 3.17 cm | 改 `build()` 里的 `Cm()` 数值 |
| 字号与行距 | 可通过 `spec["styles"]` 覆盖，但无文档 | 传 `{"title_pt":18,"body_pt":12,"line":1.5}` |

## 多轮修订

交稿之后通常还有三到八轮修改，方向经常互相拉扯：先嫌长，再嫌某节薄；先嫌章节多，再嫌没小节。这是正常的，按下面的规矩走就不会乱。

1. **一次只改一类问题**。这一轮只动字数和篇幅，下一轮只动结构，不要混在一起。
2. **改完立刻重建并自检**，把关键指标报出来：正文汉字数、节数、域数、文献条数。数字是唯一能让双方确认「确实动了」的东西。
3. **改动前备份源文件**（`cp spec.json spec_bak.json`）。脚本处理批量替换，出错是常态，能回滚比能修好更重要。
4. **批量替换先 `repr()` 打印目标片段**。pattern 差一个换行就静默 MISS，改完以为成了其实没改。
5. **删句之后必须回读该段**。逗号粘连是删句最常见的后遗症。
6. **压缩篇幅删整段，不要等比例砍**。每段都砍两成会让每节都变单薄；挑信息密度最低的整段拿掉。
7. **结构调整后整体重算**，编号、书签、交叉引用一并重新生成，不要手工补编号。
8. **同一处被连否两次，先复述用户的意思再动手**。

篇幅要用数字谈。把每节汉字数列成表，最长与最短相差三倍以上就该调整；「感觉有点长」不是可执行的信息。

## 排版故障速查

遇到下列现象查 `references/docx-pitfalls.md`，那里有成因与改法：

- 中文引号、省略号显示成西文字体的窄形
- α、β 等希腊字母变成全角宋体
- 参考文献编号和正文文字挤在一起、单双位数不对齐
- Word 标题栏显示「兼容性模式」
- 交叉引用显示「错误！未找到引用源」
- 引用编号显示成 `[[1]]`（双层方括号）
- 写入 docx 报 PermissionError，但文件明明存在
- Word COM 报 `-2147418111` 或 `RPC_E_CALL_REJECTED`
