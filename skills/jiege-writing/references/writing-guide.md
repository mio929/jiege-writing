# 写作与结构

## 课程论文的通行骨架

方法学评述类（本技能最常处理的类型）：

```
1 引言          背景 → 现状与空白 → 本文要做什么
2 方法的原理与测度   层次划分 → 技术路线 → 量化手段
3 方法的长处与局限   长处 → 技术偏差 → 解释边界 → 标准化
4 应用场景       分场景举例，每段讲清「为什么用这个方法」
5 与开题的联系     科学问题 → 研究设计 → 指标体系 → 数据处理 → 预期与可行性
6 结语          回收观点，指出方向
```

其他类型的变形：

- **纯综述**：去掉第 5 节，把第 3 节扩成「争议与不足」，结语加展望。
- **实验报告**：材料与方法 → 结果 → 讨论 → 结论，结构由学科惯例定，不强套上面的骨架。

## 篇幅配比

**先定总字数，再按占比分配，别一边写一边看。** 数字定下来，超了还是少了立刻知道，不用等到最后才发现差八百字。

### 总字数从哪来

按这个优先级取，不要自己假定：

1. 作业文件写明了 → 照文件
2. 只给下限（常见「不少于 3000 字」）→ **问一句上限**，否则容易写成两倍被嫌注水
3. 文件没写、用户也没提 → 问用户，给三个档位让他选

问的时候顺带确认**统计口径**，这三者能差三四百字：

| 口径 | 含什么 |
|---|---|
| 纯正文 | 只算正文段落，不含标题、摘要、关键词、表格、参考文献 |
| Word 字数统计 | 汉字 + 英文词 + 数字串，**含表格内文字**（学校多按这个查） |
| 页数 | 一页小四 1.5 倍行距约 700–780 字 |

### 按占比分到节

占比以**正文**为分母（不含摘要与参考文献）。摘要单列，按正文的 6%–7% 估算。

| 部分 | 占比 | 3000 字 | 5000 字 | 8000 字 | 说明 |
|---|---|---|---|---|---|
| 摘要 | 正文的 6%–7% | 180–210 | 300–350 | 480–560 | 四句话：背景、做了什么、发现什么、意义 |
| 引言 | 10%–12% | 300–360 | 500–600 | 800–960 | 三到四段，末段交代结构 |
| 主体（第 2–4 节） | 60%–65% | 1800–1950 | 3000–3250 | 4800–5200 | 每节 500–1200 字 |
| 与开题的联系 | 20%–25% | 600–750 | 1000–1250 | 1600–2000 | 课程论文的得分点，不能一笔带过 |
| 结语 | 4%–5% | 120–150 | 200–250 | 320–400 | 两段，不做新论证 |

自己算的话：`某节字数 = 目标字数 × 占比`，算完取整、写进 spec 的旁注里，写完逐节核对。

### 分配时的三条经验

- **主体别均分**。方法或原理那节通常是核心，可以占主体的四成；应用场景两三节各占一成半即可。
- **开题那节按体量缩放，不按比例缩水**。3000 字的作业里它也要有 600 字，压到 200 字就失去得分作用。
- **留 5% 余量**。写作时论证会自然膨胀，预留余量比事后硬删省力。

### 超了怎么减

删整段，不要等比例砍。每段都砍两成会让每节都变单薄；挑信息密度最低的整段拿掉，其余保持完整。

优先砍这三类：

1. 与段首重复的总结句（一段开头说了，结尾又说一遍）
2. 已有论点在别处充分展开的重复段
3. 为凑字数加的背景铺垫，删掉不影响论证链

砍完必须回读该段，检查逗号粘连。

### 少了怎么加

**按论证缺口补，不要注水。** 三类缺口最容易补出真内容：

1. **缺证据**：某个判断只有断言没有支撑，补一组数据或一个反例
2. **缺机制**：说了「A 导致 B」，没解释为什么，补中间环节
3. **缺边界**：结论没有适用范围，补「在什么条件下不成立」

反面例子是加形容词、加排比、加「综上所述」——字数上去了，评阅人一眼看得出。


## 分节粒度

- 一级章节 5–7 个。超过 8 个会显得碎。
- 二级小节只给「单节超过 800 字」的一级章节设，且每节不少于 200 字。
- 一节只有一两百字却单独设标题，读者会觉得内容不够硬凑。
- 反过来，一节塞进 1200 字以上又没有任何切分，读起来会疲劳。

判断办法：把每节的字数列出来，最长与最短相差三倍以上就该调整。

## 语体

学术中文的底线是**判断明确、有依据、不铺陈**。

- 先说结论，再给依据。不要「随着……的发展，……越来越受到关注」这类开场。
- 用具体的作者、年份、数据支撑判断，不写「大量研究表明」。
- 承认不确定性：「往往」「可能」「在多数情况下」不是软弱，是准确。
- 术语前后一致，同一个概念不要换三种说法。
- 段落开头给主题句，读者扫一眼就知道这段讲什么。

## 去 AI 味

配套 `lieflat-less-ai-tone` 技能，这里只列最常命中的几条：

| 病症 | 例子 | 改法 |
|---|---|---|
| 翻案腔 | 「不是技术问题，而是认知问题」 | 直接下判断：「关键在于认知」 |
| 顿号罗列 | 「采集、存储、展示」 | 概括或改变其中一项的句法 |
| 相邻句同构 | 连续三句都是「主语+动词+宾语，补充说明」 | 合并、拆分或换语序 |
| 破折号揭晓 | 「答案很简单——专注」 | 改成句号 |
| 提示语冒号 | 「核心是：先解决支付」 | 删提示语，直接写内容 |
| 段首路标 | 「然而」「此外」「因此」连段开头 | 把连接词挪到主语后 |
| 复述句 | 「这意味着产品找到了 PMF」 | 并入前一句 |
| 名词化 | 「完成了对流程的优化」 | 恢复动词：「把流程改顺了」 |

不要为了「像人写的」强加第一人称、口语或超短段落。学术文体本来就该是学术文体。

## 自检问句

交稿前逐条问自己：

1. 每一节的第一句，能不能独立说明这节讲什么？
2. 有没有哪一段删掉之后全文意思不变？有就删。
3. 引用的文献，每一篇都能说清「为什么引在这里」吗？
4. 有没有连续三段都以「……的」结尾？
5. 数字、年份、作者名，有没有哪一个是凭印象写的？
6. 读一遍开头三段，像不像一个人在讲一件他确实知道的事？
