# 案例复盘：一篇 4600 字方法学评述

这份复盘记录一次完整实跑，从口头需求到可提交的 docx。所有数字都来自实际产出，不是估算。

## 1. 任务与产出

用户给的条件只有一句：「主题为农田土壤水肥盐一体化智能调控方法，4500–5000 字，含 1–2 个表格，方法学评述，不署名」。

| 项 | 结果 |
|---|---|
| 题目 | 农田土壤水肥盐一体化智能调控方法评述 |
| 正文汉字 | 4637（纯段落，不含标题与表格） |
| 各级标题 | 127 |
| 摘要与关键词 | 323（摘要模板要求 250–320，略超） |
| 表题 | 31 |
| 表格内文字 | 204 |
| Word 口径合计 | **5338** |
| 一级章节 / 二级小节 | 6 / 13 |
| 参考文献 | 17 条（英文 13、中文 4），全部 DOI 复核 |
| 表格 | 2 个三线表 |
| 交叉引用域 | 文献 21 处、章节 1 处 |
| `check_docx.py --strict` | 通过，退出码 0 |

**这份字数账要特别说一句。** 目标定的是正文 4500–5000，正文 4637 达标；但 Word 口径 5338 已经超了 338 字。差的 701 字来自标题、摘要关键词与表格——这些在学校的 Word 字数统计里全都算，而写作时几乎不会有人把它们计入。

如果学校严格按 Word 5000 查，正文要压到 4300 左右。所以开写之前必须问清口径，否则写完再发现超了，删起来很疼。

## 2. 文献核验：20 个 DOI 换 17 条

先用 Crossref 的 `query.bibliographic` 按题名捞候选，再用 `works/{DOI}` 逐条回查元数据。检索阶段做了 16 个查询词，覆盖四类：fertigation、盐渍化、水盐运移模型、智慧灌溉。

三个实际遇到的问题：

**429 限流**。连续请求十几次就开始返回 429。间隔 1.5–2 秒、失败退避 4 秒重试三次，能过。中文期刊集中在同一时段查，更容易触发。

**中文期刊在 Crossref 覆盖极差**。试过 `filter=prefix:10.11975`（农业工程学报）和 `10.11766`（土壤学报），返回全空。Crossref 里搜「水肥一体化」出来的多是《水利电力技术与应用》这类非正规刊，不能用。最后中文文献走期刊官网（`tcsae.org`、`resci.cn`），官网页面上直接给了规范引用格式，比自己拼可靠。

**按题名检索会错配**。搜「fertigation review」返回的第一条是 `10.3030/720184`，那是欧盟项目编号，不是论文。所以检索只用来找 DOI，元数据必须回查。

最终 20 个 DOI 里留 17 条，弃掉 3 条：一条是 2026 年新刊期号尚未稳定、两条与论证无关（凑数会显得文献表注水）。

## 3. 结构与字数：两轮才调平

初稿写完 5062 字（超上限），分节如下：

| 章节 | 初稿 | 调整后 | 占比 |
|---|---|---|---|
| 1 引言 | 560 | 503 | 10.8% |
| 2 原理与测度 | 1420 | 1420 | 30.6% |
| 3 长处与局限 | 1140 | 1062 | 22.9% |
| 4 应用场景 | 490 | 490 | 10.6% |
| 5 与开题的联系 | 679 | 950 | 20.5% |
| 6 结语 | 211 | 211 | 4.6% |

调整动了两处，方向相反：

- **第 5 节太薄**。课程论文里「与开题的联系」是得分点，技能建议占 20%–25%，初稿只有 15.1%。补了两段（研究设计的场景合理性、预期困难三条），到 20.5%。
- **总字数超了**。按「删整段不按比例砍」的规矩，砍掉三处：引言里一句与段首重复的总结、3.2 的尺度失配段（该论点在 5.1 已隐含）、5.1 的推广背景段（最像凑数的一段）。

补 384 字、删 232 字，净减后落在 4636。

**5.2 一节初稿 707 字**，超过技能规定的单节 200–500 字，拆成 5.2（研究设计与指标体系）和 5.3（预期困难与结果）两节，拆完最大 409、最小 222，倍差 1.84。

## 4. 表格：脚本不管，得自己补

`build_docx.py` 没有 table 类型的 block。做法是正文里放一个占位段 `__TABLE_1__`，构建后用 `python-docx` 打开，定位占位段、插入表格、删掉占位段。

三线表的边框设置，关键是 `tblBorders` 只能设整表，表头下的细线得逐格设 `tcBorders`：

```python
from docx.oxml import OxmlElement
from docx.oxml.ns import qn

def three_line(tbl):
    """上下粗线 1.5pt，无竖线无内横线。"""
    pr = tbl._tbl.tblPr
    b = OxmlElement("w:tblBorders")
    for edge in ("top", "left", "bottom", "right", "insideH", "insideV"):
        el = OxmlElement("w:%s" % edge)
        if edge in ("top", "bottom"):
            el.set(qn("w:val"), "single")
            el.set(qn("w:sz"), "12")          # 1/8 pt，12 即 1.5 pt
            el.set(qn("w:color"), "000000")
        else:
            el.set(qn("w:val"), "none")
        b.append(el)
    # 顺序必须插在 tblLook 之前，否则 Word 报文件损坏
    pr.insert_element_before(b, "w:shd", "w:tblLayout", "w:tblCellMar", "w:tblLook")

def head_rule(row):
    """表头下的 0.75pt 细线，逐格设。"""
    for cell in row.cells:
        bd = OxmlElement("w:tcBorders")
        el = OxmlElement("w:bottom")
        el.set(qn("w:val"), "single")
        el.set(qn("w:sz"), "6")
        bd.append(el)
        cell._tc.get_or_add_tcPr().insert_element_before(
            bd, "w:shd", "w:noWrap", "w:tcMar", "w:vAlign", "w:hideMark")
```

三个容易翻车的细节：

1. **`tblBorders` 必须插在 `tblLook` 之前**。直接 `append` 会打乱 `tblPr` 的子元素顺序，Word 打开时提示文件损坏。
2. **表头细线不能用 `insideH`**。整表的 `insideH` 管所有内横线，表头下的那条要单独给第一行的单元格设 `tcBorders`。
3. **表格后面必须补段前距**。表格与下一段正文默认零间距，视觉上紧贴。取表格元素的下一个 `w:p`，把 `spacing/@w:before` 设成 120（6 pt）。

列宽按字符宽度估算：五号字 10.5 pt，一个汉字约 0.37 cm，单元格左右内边距各 0.19 cm。列宽 3.6 cm 大约能放 8.7 个汉字，超过就换行。第一版没算，把「Sahbeni 等；Jiang 等」挤成了「Jiang」和「等」两行，很难看。

## 5. 踩过的四个坑

**引用编号渲染成 `[[1]]`**。编号格式 `[%1]` 自带方括号，脚本又在域外手工加了一层。导出 PDF 后按 span 提取，确认是四个字符 `[[1]]`。修法是把外层 `add_run` 删掉，域缓存值直接写 `"[%d]"`。

**章节互引缺 `\h`**。文献域有 `\h`，章节域漏了，导致 `check_docx.py --strict` 报「域缺少 \h」并以退出码 1 结束——技能产出通不过自己的检查。

**不署名时多一个空段落**。`add_run(p, spec.get("author",""))` 无条件执行，作者留空就多一个 `after=18pt` 的空段，题目与摘要之间的空档明显过大。删掉即可。

**`check_docx.py` 的字数会漂**。同一份稿子，有那个空作者段时报 4943，删掉后报 4678。因为统计起点写死为 `text[2]`，假设前两段必是题目和作者。交付时要说明用的是哪个口径。

## 6. 复现步骤

```bash
# 1. 装依赖
pip install python-docx lxml

# 2. 读要求，整理成清单（references/checklist.md 第一份）

# 3. 核验文献，写进 spec.json 的 refs

# 4. 写正文，blocks 里用 {{文献键}} 标引用

# 5. 构建
python scripts/build_docx.py spec.json -o 论文.docx

# 6. 如有表格，用后处理脚本插入

# 7. 自检
python scripts/check_docx.py 论文.docx --strict

# 8. 目视：分页、表格、中英文混排、文档属性
```

第 8 步不能省。脚本查不出分页难看、表格断裂、`docProps/core.xml` 里残留的 `creator=python-docx`。
