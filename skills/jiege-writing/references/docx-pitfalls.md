# 排版踩坑清单

按「现象 → 成因 → 改法」组织。多数问题在 `scripts/build_docx.py` 里已经处理过，此处记录原因，便于排查新问题。

## 字体类

### 中文引号、省略号显示成西文字体的窄形

**成因**：`“ ” ‘ ’ …` 处在 Unicode 的「两可」区间，Word 按上下文决定用 `ascii/hAnsi` 还是 `eastAsia`。只设 `eastAsia="宋体"` 不够。

**改法**：给含中文的 run 加 `w:rFonts ... w:hint="eastAsia"`。判断依据是文本里是否含 CJK 汉字或全角标点。

### α、β 变成全角宋体

**成因**：希腊字母 U+0370–03FF 也落在两可判定里，被 run 上的 `hint="eastAsia"` 一把推给了宋体。

**改法**：按字符类别**拆 run**，希腊字母单独成 run，四个字体位全部写 Times New Roman 并设 `hint="default"`。注意 `βNTI` 要拆成 `β` 与 `NTI` 两段，拆完视觉无变化，但字体归属对了。

### 样式里的主题字体改不掉

**成因**：`styles.xml` 中 `w:pPr/w:rPr/w:rFonts`（段落标记属性）常挂着 `asciiTheme`/`hAnsiTheme`/`eastAsiaTheme`/`cstheme`，而主题字体的优先级高于显式字体名。只遍历 `w:style/w:rPr` 会漏。

**改法**：`for rf in styles.element.iter(qn('w:rFonts'))` 全量遍历，先删主题属性再写字体名。改完用 `grep asciiTheme` 复核，应为 0。

## 编号类

### 编号和正文挤在一起、[1] 与 [27] 后文字不对齐

**成因**：列表定义里 `w:suff` 为 `space` 时，编号后只跟一个空格，文字起点随编号宽度浮动。

**改法**：`w:suff w:val="tab"`，同时在段落上设 `w:tabs` 制表位（与悬挂缩进同值，如 420 twips），文字就固定对齐到制表位。

### 参考文献编号是「1」不是「[1]」

**成因**：`w:lvlText` 只写了 `%1`。

**改法**：`w:lvlText w:val="[%1]"`。Word 的「段落编号」交叉引用会把 lvlText 里的字面方括号一起带出，所以正文引用处**不要再另加括号 run**，否则变成 `[[1]]`。

## 域类

### 交叉引用显示「错误！未找到引用源」

**成因**：bookmark 名与 `REF` 域里的名字不一致，或 bookmark 被删。

**改法**：域代码形如 ` REF _RefW001 \n \h `，要求 `bookmarkStart w:name="_RefW001"` 存在且包裹目标段落。批量生成时把编号写进书签名（`_RefW%03d`）最稳。

### 引用编号不能点击跳转

**成因**：`REF` 域没加 `\h` 开关。

**改法**：` REF _RefW001 \n \h `。Word 默认要 Ctrl+单击；想改单机跳转，去「文件→选项→高级→编辑选项」取消「用 Ctrl+单击跟踪超链接」。

### 更新域后编号变空或重复

**成因**：缓存值（`separate` 与 `end` 之间的文本）与真实编号不一致，且域从未更新过。

**改法**：生成时把缓存值写成正确编号，用户打开即正确；日后按 Ctrl+A → F9 会重算，结果一致。

### 合并引用出现 [1][2][3]，或 [4,5] 该写成 [4-5]

**成因**：每条文献的 `REF` 域各自输出一对 `[ ]`，拼在一起就是 `[1][2][3]`；另外把两篇连续文献用逗号并列，不符合 GB/T 7714「遇连续序号，起讫序号间用短横线连接」。

**改法**：给域加数字图片开关，让括号只归属首尾两个域：

| 位置 | 开关 | 输出 |
|---|---|---|
| 第一个 | `\#"[0"` | `[1` |
| 中间 | `\#"0"` | `1` |
| 最后一个 | `\#"0]"` | `1]` |

域代码形如 ` REF _RefW001 \n \h \#"[0" `。中间的分隔符（`,`、`-`）用普通 run，仍设为上标。这样做的好处是每个编号依然可 Ctrl+单击跳转，比整段纯文本强。`build_docx.py` 的 `add_citation()` 已实现，不要手写。

连续两篇同样用短横线：`[4-5]`。判断依据是序号是否相邻，不是数量是否达到三篇。

## 表格类

### 设了三线表边框，Word 打开提示文件损坏

**成因**：`w:tblBorders` 被直接 `append` 到 `tblPr` 末尾，打乱了 `tblPr` 的子元素顺序（schema 要求 `tblBorders` 在 `tblLook` 之前）。

**改法**：用 `insert_element_before` 指定后继元素：

```python
pr.insert_element_before(borders, "w:shd", "w:tblLayout", "w:tblCellMar", "w:tblLook")
```

同理，`w:tcBorders` 要插在 `w:shd`、`w:noWrap`、`w:tcMar`、`w:vAlign` 之前。

### 表头下的细线设不上

**成因**：整表的 `insideH` 管所有内横线，一设就把每行之间都画上；不设则表头下也是空的。

**改法**：`tblBorders` 里把 `insideH` 设为 `none`，再给第一行每个单元格单独加 `tcBorders` 的 `bottom`（`sz="6"`，即 0.75 pt）。

### 表格紧贴下一段正文

**成因**：表格不是段落，`spacing` 不作用于它；表格后第一个段落若 `before=0`，视觉上就贴住了。

**改法**：取 `tbl._tbl.getnext()` 找到下一个 `w:p`，把它的 `pPr/spacing/@w:before` 设成 120（6 pt）。注意要在删除占位段**之后**再找，否则找到的是占位空段。

### 单元格里的文字断得很难看

**成因**：列宽按「总宽 ÷ 列数」平均分，没考虑五号字一个汉字约 0.37 cm、单元格左右内边距各 0.19 cm。

**改法**：按实际字数分配列宽，并在内容里用换行符分段，把换行点控制在语义边界（如两篇文献之间），不要让它自己断在「Jiang」和「等」中间。

## 图类

### 图在页底，图注单独跑到下一页

**成因**：`keepNext`（与下段同页）对含内嵌图片的段落不可靠。图片 11.5 cm、页底只剩 6 cm 时，Word 仍把图留在原页，只把图注推走。这不是设置没生效，是 Word 对 drawing 对象的排版取舍——图片本身能塞进剩余空间，它就不管下一段。

**改法**：图和图注放进同一个单元格，表格行加 `<w:cantSplit/>`，整行不许跨页。`scripts/insert_figs.py` 已这么做。别试图用「插入分页符」硬调，改一次内容就全乱。

### 图注压住图片下缘

**成因**：图与图注写进同一段落（图 run + `add_break()` + 文字 run）。内嵌图片的高度不计入行高计算，行距设成 1.0 时，行高按 9 pt 文字算，图片溢出到段落下方，压住图注。

**改法**：单元格内拆成两个段落。图片段 `space_after=3 pt`、`line_spacing=1.0`；图注段 `space_before=3 pt`。表格本身不需要边框，`tblBorders` 全 none + `tblCellMar` 归零，肉眼看不出来。

### 图注里的编号与正文对不上

**成因**：图注里用了 `{{键}}`。`build_docx.py` 按「首次出现」编号，图注在正文之前出现时会把次序带偏；即使位置正确，图注加入排序也会让后面所有编号平移。

**改法**：图注写 `@键@`，由 `insert_figs.py` 按**正文**的首次出现顺序换算成 `[n]`。`--check` 会把每张图的最终图注打出来，编号错了当场能看见。

## 文档属性类

### Word 标题栏显示「兼容性模式」

**成因**：`settings.xml` 里 `compatibilityMode` 为 14 或更低，且带 `w:useFELayout`（旧版东亚版式）。

**改法**：改成 15，删掉 `useFELayout`。

## 环境类

### 写入 docx 报 PermissionError，文件明明存在

**成因**：文件被预览器（WPS、Tencent Docs 预览面板、Word）以「允许读、拒绝写」的方式打开。此时 `open('r+b')`、`shutil.copyfile`、`os.remove`、`os.rename` 全部失败，但读正常。

**改法**：另存新名交付；或把预览面板切到别的文件，锁会随之释放；实在不行就关掉占用程序。不要反复重试同一路径。

### Word COM 报 `-2147418111 被呼叫方拒绝接收呼叫`

**成因**：会话处于锁屏/非交互状态，或存在多个残留的 `WINWORD.EXE`。此时 `Documents.Open` 一调就挂，但 `app.Name` 之类的静态属性还能读。

**改法**：改用纯 OOXML 操作，不要依赖 Word 渲染。清理残留进程时按「无窗口标题 + 启动时间在最近若干分钟」精确筛选，别误杀用户正在编辑的窗口。

### Word COM 报 `0x80010001 RPC_E_CALL_REJECTED`

**现象**：`Documents.Open` 能成功，但随后的 `ExportAsFixedFormat`、`SaveAs2`、`ComputeStatistics` 全部被拒。加延时重试、改 `Visible=$true`、杀进程重来、换文件名，都不稳定。

**成因**：隐藏实例的 UI 消息泵没有在跑，Word 在等一个模态对话框（未激活提示、登录窗、受保护的视图）时会把所有自动化调用挡回去。

**改法**：别在 docx 校验环节依赖 Word 导出 PDF。改为「在 Word 里人工目视」这一条，或用 LibreOffice 命令行兜底：

```bash
soffice --headless --convert-to pdf 论文.docx
```

真要用 COM，先把 Word 手动打开一次、登录并关掉所有弹窗，再跑脚本。

### 读 PDF 要求文件读出乱码

**成因**：PDF 内容流是 Flate 压缩，直接按文本读会得到二进制。

**改法**：`pip install pymupdf`，用 `fitz.open(path)[i].get_text()`。压缩包内的 `~$` 开头文件是 Office 的锁文件，可安全删除。

## 文本类

### 删句之后出现逗号粘连

**成因**：为压字数删掉一个分句，留下「……，要确立因果关系……」这类残缺。

**改法**：删句后必须回读该段，把该断的地方换成句号。批量改动用脚本时，改完先 `print` 出受影响段落逐条看。

### 章节编号引用读起来别扭

**现象**：「沿用第2节的扩增子路线」放在句首，读者被迫回翻。

**改法**：中文正文里尽量不写「第 X 节」。要么把话说完整（「按梅花形五点混样」），要么用「见 2.2 节」这种短形式放在句末括注里。只有确实需要指路的导读段才写节号，且全文不超过四五处。
